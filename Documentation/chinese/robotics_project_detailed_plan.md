# 机器人项目——详细实施计划

## 1. 项目目标与范围

比较**随机（Random）、最近（Nearest）、信息增益（Information Gain）和 LLM 引导的前沿选择**在室内物体搜索中的表现。初始任务是**通过视觉检测指定类别的目标**，例如杯子。靠近、抓取和操作物体不属于初始范围。

标准实验是**在已知房间布局先验和机器人位姿的条件下进行物体搜索**。初期采用单楼层、固定安装的 RGB-D 相机和静态场景。允许输入仿真器位姿和经过标定的相机坐标变换，不要求实现 SLAM。完整房间多边形会揭示尚未观察到的房间布局及范围，但不提供障碍物占据信息或物体位置。

所有策略共用感知、候选生成规则、可行性筛选、观察流程、导航和预算。在相同状态下，各策略获得相同的合格候选集合。策略采取不同路线后，实际地图和前沿集合自然会不同。

模块行为以[接口约定](interface_freeze.md)为准。

## 2. 工作分工

| 负责人 | 职责 | 职责边界 |
|---|---|---|
| A——感知与建图 | RGB-D、占据与覆盖情况、物体跟踪及目标发现声明、房间关联、前沿及信息增益；仅用于评估的目标验证器 | 不选择目的地，不向机器人暴露评估器的真值数据 |
| B——导航与规划 | 仿真器适配器、坐标变换、控制、导航代价地图、候选可行性与代价、规划、执行、固定观察动作 | 不按搜索价值为前沿排序 |
| C——搜索策略与运行器 | 四种策略、回合运行器、恢复状态记录、实验配置、日志与比较 | 不构建地图，不实现路径规划 |

C 负责端到端集成和运行器。B 负责仿真步进与控制集成；A 负责独立的目标验证器。三人共同审查接口约定的变更，并验证各自模块的边界。

## 3. 系统架构

```text
运行器初始化模块、先验、随机种子和预算
    ↓
B 执行初始观察流程；A 处理 RGB-D
    ↓
A 发布 WorldState：地图、物体、区域和前沿
    ↓
B 评估候选可行性和路径代价
    ↓
运行器应用共用的恢复排除规则
    ↓
C 选择一个合格前沿
    ↓
B 导航；A 观察；运行器执行限制检查
    ↓
B 完成到达后的观察流程；A 发布最新状态
    └── 重复

任何时刻出现目标发现声明 → 停止运动 → 隔离的验证器
                                      → success 或 false_target_claim
```

运行器在模块间传递 `WorldState`、`CandidateEvaluation`、`SelectionContext`、`Subgoal` 和 `NavigationFeedback`。候选评估不会移动机器人，也不会选择目的地。规划可行、执行完成和正确检测目标是三个独立结果。

## 4. A——感知与建图

### RGB-D 与可通行性

在运动和固定观察流程中采集 RGB-D。感知频率可以低于仿真频率；每个已处理帧都保留其序列号、仿真时间戳和采集时的坐标变换。

A 构建未知、已知空闲和被占据三类栅格。未知栅格不可通行。使用经过标定的深度、地面估计和机器人竖直方向的碰撞包络推导占据状态。看到桌面，或观测射线从低矮障碍物上方经过，并不能证明下方有足够空间让机器人通过。无效深度和未观察到的体积保持未知。所有策略使用相同的地面容差、深度范围、高度滤波和证据阈值。

A 发布物理占据证据；B 单独构建考虑机器人占地轮廓的导航代价地图。不要在 A 的地图中预先加入机器人障碍物膨胀。

### 覆盖情况与房间先验

几何观察覆盖情况与占据状态分别维护。`explored_fraction` 表示房间多边形内具有有效几何观察证据的栅格比例。它**不能**证明所有桌面和搁架均已检查，也不能证明目标不存在。面向物体检查的覆盖模型可作为后续可选工作。

完整房间多边形和仿真器位姿属于标准实验允许的先验。使用不包含语义标签的不透明房间 ID。除明确允许的初始占地范围无碰撞种子外，物体、占据状态和前沿均来自机器人观察。语义房间标签默认隐藏，只有在所有策略均可使用标签的真值标签（oracle-label）实验中才启用。验证器只能通过隔离的评估接口访问隐藏数据。

### 物体与目标发现声明

使用 RGB 检测、深度和采集时坐标变换，将检测结果关联成物体轨迹。在 W1 检查检测器类别标签，以及它在选定目标和渲染场景上的表现。

必须进行多帧确认。配置置信度、不同帧数量、时间窗口和空间一致性要求。重复处理同一帧不能增加确认次数。已确认的轨迹产生包含轨迹 ID 和证据观察 ID 的 `TargetClaim`。

机器人收到该声明后停止。仅用于评估的验证器按照固定匹配规则，检查证据是否对应指定类别的可见物体实例。错误声明以 `false_target_claim` 结束回合；验证器不会让策略恢复搜索。因此，真值不能指导后续搜索。

### 前沿与信息增益

提取已知空闲栅格与未知栅格之间的边界，并进行确定性聚类。在已知空闲的一侧选择接近位姿，到达朝向指向未探索区域。B 仍需验证机器人全身的碰撞净空和可达性。

使用相机量程、视场、接近朝向和固定到达扫描过程估计 `information_gain_m2`。每个预计可见的未知栅格只计数一次，遇到已知遮挡物时停止射线。无法使用隐藏障碍物信息，因此信息增益只是估计值。所有策略使用固定且相同的估计方法与参数。

匹配成功的前沿簇保留 ID。分裂或合并时记录父级 ID，并暴露构成前沿的栅格集合，使恢复历史能够通过空间重叠传递。新 ID 不能清除失败或无进展历史。匹配和重试行为由接口约定定义。

“继续深入这个房间”是对前沿选择的解释，并非特殊的底层动作。

## 5. B——导航与运动规划

### 选择前先评估

`B.evaluate_candidates(...)` 基于同一地图修订版本和当前位姿，返回可达性与路径长度估计。使用与执行规划器相同的运动模型和代价地图。对于适合的机器人，栅格距离场可以摊薄计算开销；否则采用有计算上限的逐候选规划。评估超时表示可行性未知，不代表已证明不可达。

所有策略从通过共用恢复筛选且被评估为可达的候选中选择。B 不选择最有搜索价值的前沿。开始执行时应重新验证规划，因为地图或位姿可能已经变化。

### 导航几何

规划器由团队实现，iGibson 用作仿真器。对于能够原地转向的圆形机器人，A* 是合适的初始方案；否则应选择满足机器人约束的规划器。

集成前确定占地轮廓、碰撞高度范围、净空裕量、运动限制、位置及偏航到达容差和地图分辨率。圆形轮廓可采用保守的障碍物膨胀，其他情况可使用考虑朝向的轮廓检查。检查完整路径段和旋转过程，禁止斜向切角以及机器人轮廓与未知空间重叠。

只有经过验证的初始占地范围净空，才能在明确记录的出生位置净空先验下初始化起始可通行区域。不要暴露额外的仿真器空闲空间。扫描动作也必须进行碰撞检查。

### 执行与失败

B 执行选定目标、接收更新地图，并可对同一目标重新规划。规划结果与最终执行状态分别报告。

基础版本包含 `NO_PATH`、`BLOCKED`、`TIMEOUT` 和 `INVALID_GOAL`。详细几何证据及面向 LLM 的失败推理仍属可选项。操作必须有截止时间；取消操作具有幂等性，包括尚未产生路径时的取消。

## 6. C——搜索策略

运行器提供状态、评估和合格候选 ID。策略仅在选择规则上不同。稳定排序和确定性平局处理使用前沿 ID；Random 使用独立且已记录的随机数流。

| 策略 | 选择规则 |
|---|---|
| Random | 在合格候选中均匀随机选择 |
| Nearest | 选择评估路径长度最小的候选 |
| Information Gain | 最大化 `information_gain_m2 / (path_cost_m + epsilon_m)` |
| LLM-guided | 根据目标、已观察物体、区域摘要、信息增益、路径代价和共用恢复上下文，选择合格 ID |

在配置中固定正数 `epsilon_m`。欧氏距离用于诊断，不作为标准 Nearest 基线的代价。

LLM 返回合格 ID；适配器从 A 的接近位姿构造子目标。未知房间标签保持未知，但模型可推理可能的房间类型。不得提供像素、隐藏物体数据、评估器结果，或真值条件之外的语义标签。

设置实际时间截止限制和调用次数上限。无效、超出候选集合或超时的响应使用确定性 Nearest 回退，并记录原因。记录准确模型标识、受支持的推理配置、提示词、符号化输入、响应和回退情况。

## 7. 固定观察与持续感知

相机固定在机器人上。仅靠正常路径跟随不能保证获得足够视角。运行器为所有策略调用相同的预设流程：

1. 初始化时执行经过碰撞检查的朝向扫描。只有机器人约束和净空允许时才进行完整旋转。
2. 到达前沿后，先达到面向未知空间的规定朝向，再执行配置好的有限扫描。
3. 等待 A 处理该观察动作产生的新帧，然后重新评估候选。
4. 宣布没有前沿或没有可行前沿之前，允许一次有界的恢复观察循环，再刷新状态与评估。

B 通过 `start_observation` 执行这些流程；基础版本中，C 不选择扫描动作。扫描角度、采样与停留要求、各项限制均为所有策略共用的固定配置。不安全或超时的扫描返回明确类型的失败，不得无限循环。

这里的**基础版本（baseline）**指用于比较四种前沿选择策略的第一个实现。环视是机器人共用行为中自动执行的部分。运行器判断何时应执行规定流程，B 控制机器人转向，A 处理相机看到的内容。相机仍固定在机器人上；`start_observation` 请求的是观察运动，并非物体检测或单独按下相机快门的动作。

例如，选择一个前沿之后：

1. **C 选择 F3：**“前往这个前沿。”
2. **B 导航至 F3**，并报告到达。
3. **运行器调用 `B.start_observation(...)`** 执行到达观察流程；安全条件允许时，B 按预设角度转向。
4. **A 处理相机观察结果**，更新地图与检测。运行器等待所需新观察，并从 B 获取更新后的候选评估。
5. **C 选择下一个前沿**，除非目标发现声明或其他停止条件已经结束搜索。

每种策略都使用相同观察规则，因此实验比较的是前沿选择，而不会同时改变扫描的选择方式。让 C 决定“在这里再扫描一次”或“检查这个区域”属于后续可选扩展，会将策略动作空间扩大到前沿选择之外。

导航期间持续进行感知。目标发现声明会触发立即取消。策略决策发生在初始化、到达观察完成后，或失败与恢复之后，而不是每一图像帧。

## 8. 恢复、进展与回合控制

运行器应用共用规则：

- `NO_PATH`/`INVALID_GOAL`：暂时排除候选，直到相关可通行性、接近几何或机器人连通性发生变化。
- `BLOCKED`/`TIMEOUT`：使用配置好的冷却期和有界重试，随后重新评估可行性。
- 在有空间重叠的分裂或合并间传递排除状态和重试历史。仅全局修订号增加，不足以重试几何失败。
- 到达后，将局部未知面积的减少量与配置的进展阈值比较。排除已到达却未揭示新区域的前沿；重复无进展尝试必须在固定预算内终止。
- 限制每回合尝试次数、仿真步数、仿真时间和实际时间。地图变化不能重置全局上限。
- 下发前重新验证过期选择。刷新失效候选，不以任意坐标替代。

若没有合格候选，执行有界恢复观察，在预算内等待尚未结束的冷却期，并重新评估。之后才能以 `no_frontiers`、`no_feasible_frontiers` 或 `search_limit` 终止。前沿耗尽不能证明物体不存在。

## 9. 实验协议

正式运行前冻结实验配置清单：

- 各策略使用配对的场景、起始位姿和目标实例配置，包括初始朝向。仅评估器可进行的检查用于确认目标存在，并可从某个可达视点看见。
- 使用多组随机种子重复实验；环境、策略和随机感知使用独立随机数流。固定场景资源、检测器权重、机器人及相机配置和地图参数。
- 共用仿真与感知频率、观察流程、候选提取、可行性限制、恢复规则及回合预算。
- 标准先验包括已知房间布局、已知位姿和出生位置占地净空。真值语义标签条件单独报告。
- 所有策略均在决策边界暂停仿真并让机器人停止，包括候选评估和 LLM 调用期间。导航和扫描时继续仿真及感知。单独测量决策实际耗时，并执行实际时间限制。

报告**所有**回合的成功率、错误声明率、终止原因、实际执行路径长度、仿真搜索时间、实际时间、碰撞、重新规划、无进展尝试和前沿访问次数。仅成功回合的效率指标应标注样本数，不得悄悄删除失败回合。采用配对比较，并基于重复试验给出不确定性区间。

LLM 实验还需报告调用次数、延迟、token 用量、回退率，以及可获得时的成本。保留原始日志和配置清单。仅有随机种子并不能保证托管模型完全可复现。

可选消融：移除 LLM 输入中的语义证据，增加固定语义启发式基线，或启用单独标记的真值房间类型条件。先完成四种核心策略。

## 10. 实施优先级

| 优先级 | 功能 |
|---|---|
| 必须完成 | RGB-D 建图、前沿跟踪、多帧目标发现声明、隔离验证器、考虑占地轮廓的规划器、候选评估、固定观察、有界恢复、四种策略、自动运行器及日志 |
| 应当完成 | 多场景可靠性、失败分析、重复配对试验和不确定性估计 |
| 时间允许再做 | 详细规划证据、语义消融、策略自主选择检查动作、途中高层重新决策 |

基础版本是基于前沿的视觉搜索，不是穷尽式检查。场景在几何上已探索但目标仍未看见，是需要记录的限制，不能以此为由暴露隐藏仿真信息。

## 11. 六周时间表

| 周次 | A——感知与建图 | B——导航与规划 | C——策略与运行器 | 里程碑 |
|---|---|---|---|---|
| W1 | RGB-D 约定、先验加载器、检测器可行性、建图器重置 | 仿真步进与变换、机器人几何、初始控制 | 接口测试数据、运行器骨架、模拟 Random/Nearest、实验清单 | 配置与接口达成一致；观察数据贯通模块 |
| W2 | 占据与覆盖、前沿及身份、信息增益 | 规划器、代价地图、批量评估、观察运动 | 运行器与恢复、Information Gain、LLM 适配器 | 地图扩展，共用可行候选驱动导航 |
| W3 | 轨迹、声明、房间关联、验证器 | 持续地图更新、失败、取消 | 集成全部策略、限制与日志 | 单场景完成独立评分的搜索 |
| W4 | 建图与检测修复 | 净空、过期目标、受阻路径及超时 | 配对预实验、预算与回退验证 | 可靠性用例通过；冻结正式配置 |
| W5 | 正式实验及感知分析 | 正式实验及导航分析 | 核心比较，获得结果后再做可选消融 | 完整实验数据集 |
| W6 | 感知与评估报告章节 | 导航报告与演示支持 | 分析、复现材料、报告整合 | 最终报告与演示 |

W4 用例：目标在起始房间或其他房间；途中看见目标；目标最初位于机器人身后；重复误检；狭窄门口；不可达或暂时受阻前沿；分裂与合并；到达却无新观察；规划前取消；LLM 超时或无效输出。

W6 避免重大算法变动。在 W1–W2 使用合成状态、评估、子目标和反馈测试数据开发模块，不必彼此等待。

## 12. 端到端示例

目标是杯子。初始观察流程结束后，A 在 R1 观察到沙发和桌子，并生成两个前沿接近位姿。B 评估两者；C 按其策略选择一个。

B 导航，A 同时建图。在门口，A 观察到 R2 的水槽和冰箱。到达后，B 面向未知空间并执行固定扫描。A 处理新帧；B 刷新可行性和代价。LLM 可能根据已观察物体偏向 R2；Nearest 最小化路径代价；Information Gain 最大化增益与代价之比。

下一段路线中，A 在不同帧中确认杯子轨迹并发出声明。运行器取消导航、冻结证据并调用隔离验证器。匹配到可见杯子则得到 `success`；误检则得到 `false_target_claim`。两种结果均保留在实验结果中，并附带距离、时间和回退信息。
