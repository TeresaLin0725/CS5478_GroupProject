# 流水线超时修复

修复 Windows 下日志与 watchdog 文件写入阻塞导致的运行器超时误判。B 的导航、A 的感知及策略选择逻辑均不变。

- 模块超时只使用函数执行结束时记录的耗时；开始、结束日志的等待不算作模块执行时间。
- 新冻结的实验使用共享内存 watchdog。父进程读取一致的快照，避免每次模块调用都更新和替换文件。旧协议仍支持 JSON watchdog。
- 新实验的证据日志由单个后台线程按顺序写入；正常退出前等待写完。写入错误或队列溢出会报错，不会静默丢弃证据。强制终止进程仍可能丢失尚未写出的尾部事件，因此不能将被强制终止的回合当作成功。
- 新增可选 `initialization_deadline_s`，默认不设置，保留旧清单行为。基准冻结器为新实验设置初始化 240 秒、首次遥测前启动 300 秒；搜索的仿真、单次操作和整回合墙钟限制不变。
- 共享内存中的当前模块期限仍由父进程监督，旧的日志完成事件不能掩盖新的模块卡死。父进程终止 worker 后，从已写入事件恢复 LLM 调用导出。

验证：跨进程读写、半写入快照拒绝、磁盘阻塞期间执行不受阻、证据有序保存、写入错误上报、真实模块超时、独立初始化期限与旧清单兼容性。

仅对新冻结的源码快照和协议生效；历史实验及其清单、结果不应原地改写。墙钟耗时仍会受系统调度和并发资源竞争影响，这次修复不保证所有 `search_limit` 都消失。
